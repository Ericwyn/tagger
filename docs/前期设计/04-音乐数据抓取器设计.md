# 音乐数据抓取器设计

## 1. 目标

抓取器的职责是“寻找并解释外部元数据候选”，不是直接修改本地文件。它需要：

- 支持网易云、酷我、Apple Music 等来源。
- 同时兼容 MusicBrainz、Cover Art Archive、LRCLIB 等开放来源。
- 每个来源只实现自己真正支持的能力。
- 多来源可并行，单源失败互不影响。
- 所有候选转换为统一模型，并保留字段级来源。
- 支持限流、重试、缓存、健康检查、秘密配置和失效降级。
- 匹配分数可解释；默认由用户确认后才应用。

## 2. 策略模式

不要定义一个要求所有方法的巨大 `Provider` 接口。否则不支持歌词的来源只能返回空实现，业务层无法区分“没有歌词”和“调用失败”。

使用描述器 + 小能力接口：

```go
type Descriptor struct {
    ID           string
    Name         string
    Version      string
    Experimental bool
    Capabilities []Capability
}

type Provider interface {
    Descriptor() Descriptor
    Health(ctx context.Context) Health
}

type TrackSearcher interface {
    SearchTracks(ctx context.Context, q TrackQuery) ([]TrackCandidate, error)
}

type TrackGetter interface {
    GetTrack(ctx context.Context, id ExternalID) (TrackCandidate, error)
}

type AlbumSearcher interface {
    SearchAlbums(ctx context.Context, q AlbumQuery) ([]AlbumCandidate, error)
}

type AlbumGetter interface {
    GetAlbum(ctx context.Context, id ExternalID) (AlbumCandidate, error)
}

type LyricsFetcher interface {
    GetLyrics(ctx context.Context, ref TrackRef) ([]LyricsCandidate, error)
}

type ArtworkFetcher interface {
    GetArtwork(ctx context.Context, ref AlbumRef) ([]ArtworkCandidate, error)
}

type FingerprintMatcher interface {
    MatchFingerprint(ctx context.Context, fp Fingerprint) ([]TrackCandidate, error)
}
```

注册表：

```go
type Registry interface {
    Get(id string) (Provider, bool)
    Enabled(cap Capability) []Provider
    Describe() []Descriptor
}
```

编译期注册保证单二进制和类型安全。第一版不使用 Go `plugin`。

## 3. 统一候选模型

```go
type TrackCandidate struct {
    Source       SourceRef
    Title        Sourced[string]
    Subtitle     Sourced[string]
    Artists      Sourced[[]ArtistCredit]
    Album        Sourced[AlbumSummary]
    Track        Sourced[IndexValue]
    Disc         Sourced[IndexValue]
    DurationMS   Sourced[int64]
    ReleaseDate  Sourced[PartialDate]
    OriginalDate Sourced[PartialDate]
    Genres       Sourced[[]string]
    ISRCs        Sourced[[]string]
    ExternalIDs  map[string][]string
    LyricsRefs   []ExternalRef
    ArtworkRefs  []ExternalRef
    Score        MatchScore
    RawCacheKey  string
}

type Sourced[T any] struct {
    Value      T
    Source     SourceRef
    Confidence float64
}

type SourceRef struct {
    ProviderID string
    ExternalID string
    URL        string
}
```

每个 provider 先返回自己的完整候选。聚合层可以生成 composite candidate，但每个字段的 `SourceRef` 不变。

不把远程响应原封不动传给前端：

- 防止 provider schema 变化扩散到 UI。
- 防止响应包含 cookie、追踪 URL 或超大字段。
- 便于缓存版本化和 golden test。

每个来源还要公开用途政策，控制 UI 能否提供“写入文件”选项：

```go
type UsagePolicy struct {
    CanDisplayMetadata   bool
    CanPersistMetadata   bool
    CanDisplayArtwork    bool
    CanPersistArtwork    bool
    CanPersistLyrics     bool
    RequiresAttribution  bool
    AttributionText      string
    TermsURL             string
}
```

用途政策是产品保护栏，不是法律结论。来源条款变化时只需更新 adapter policy 和文案，不应让前端自行猜测。

## 4. 数据源规划

### 4.1 能力矩阵

| 数据源 | Track Search | Album | Artist | Lyrics | Artwork | Track/Disc | 身份要求 | 阶段 |
|---|---:|---:|---:|---:|---:|---:|---|---|
| MusicBrainz | 是 | 是 | 是 | 否 | 间接 | 是 | User-Agent | MVP |
| Cover Art Archive | 否 | release/release-group | 否 | 否 | 是 | 否 | 无 | MVP |
| LRCLIB | 精确/搜索 | 否 | 否 | plain/LRC | 否 | 否 | User-Agent | MVP |
| Apple Music API | 是 | 是 | 是 | 视 API 数据 | 是 | 是 | Developer Token | MVP/P1 |
| iTunes Search | 是 | 是 | 是 | 否 | promo art | 是 | 无 | MVP fallback |
| 网易云 | 是 | 是 | 是 | 是 | 是 | 是 | 非官方接口/可选 cookie | Experimental |
| 酷我 | 是 | 是 | 是 | 是 | 是 | 是 | 非官方接口 | Experimental |
| AcoustID | 指纹 | release 信息 | 间接 | 否 | 否 | 间接 | API key | P2 |

“支持”表示 adapter 可以表达该能力，不表示每条记录都包含该字段。

### 4.2 MusicBrainz

主结构化数据源：

- 优先通过 embedded MBID/ISRC 精确查询。
- 文本搜索使用 recording/release。
- album candidate 获取 media、track、disc、artist credit、release date、country/status。
- Cover Art Archive 使用 release MBID 或 release-group MBID。
- 保存 MusicBrainz Recording、Release、Release Group、Release Track、Artist ID。

[MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API) 要求每客户端每秒最多一次请求和可识别 User-Agent。实现使用专用 limiter，不因批量任务并发绕过限制。

### 4.3 Apple Music 与 iTunes Search

正式 Apple Music adapter：

- 使用 `/v1/catalog/{storefront}/search` 和资源详情。
- 配置 storefront，默认不能写死 US。
- 开发者 token 在服务端生成/读取，不下发给浏览器。
- token 缓存并在过期前刷新。
- 429 按官方响应退避。

[Apple Music token](https://developer.apple.com/documentation/AppleMusicAPI/generating-developer-tokens) 需要 MusicKit identifier、私钥、Team ID、Key ID 和 ES256 JWT。UI 设置页只保存引用或加密值。

iTunes Search adapter：

- 作为无需开发者账号的搜索 fallback。
- 结果包含 title、artist、album、duration、track/disc 和 genre，适合候选匹配。
- [官方文档](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/Searching.html) 说明约 20 calls/minute 且建议缓存。
- promotional artwork 的持久化使用受官方条款限制，因此默认 `CanPersistArtwork=false`；只可用于符合条款的展示，不能直接作为“嵌入封面”来源。

### 4.4 LRCLIB

- 先调用精确 `/api/get`，传 title、artist、可选 album 和 duration。
- duration 是强匹配字段；官方文档说明通常要求在 ±2 秒内。
- 精确失败后才使用 search。
- 同时返回 plain 和 synced LRC 时都保留，由用户选择。
- 识别 instrumental，不写入 `[Instrumental]` 假歌词。
- 必须设置 User-Agent、顺序请求并尊重 `Retry-After`。

### 4.5 网易云与酷我

实现原则：

- 标记 `Experimental=true`，默认关闭。
- 只实现元数据、歌词和封面，不实现音频 URL、试听解锁或下载。
- 签名、cookie 和 endpoint 代码完全封装在 provider 目录。
- adapter 必须有 fixture/golden test，线上响应变化时只影响该 provider。
- UI 显示“非官方接口，可能失效并可能受平台条款限制”。
- 用户提供的 cookie 视为秘密，不记录、不返回、不包含在导出诊断中。
- 未配置 cookie 时只调用确实无需登录的能力。

可参考但不直接复制：

- music-tag-web 的 [NetEase/MiGu/QMusic adapter](https://github.com/xhongc/music-tag-web/blob/077fcc4625dc7fc9e7a1bee78ae1fcc17ad23edc/applications/task/services/music_resource.py)。
- [Meting](https://github.com/metowolf/meting) 的统一来源概念。
- [go-music-api](https://github.com/guohuiyuan/go-music-api) 的来源矩阵和统一 REST 形状。该项目为 AGPL-3.0，本项目不应直接引入或复制实现，除非许可证策略明确接受。

## 5. 查询构建

优先级从高到低：

1. 精确外部 ID：MusicBrainz ID、provider song ID。
2. ISRC。
3. 指纹（未来）。
4. title + primary artist + album + duration。
5. title + primary artist + duration。
6. 从文件名解析 title/artist 后搜索。

文件名解析只生成 query hint，不直接写标签。保留原始值：

```go
type TrackQuery struct {
    Title       string
    Artists     []string
    Album       string
    DurationMS  int64
    ISRCs       []string
    ExternalIDs map[string][]string
    FileName    string
    Limit       int
}
```

## 6. 规范化

用于比较的 normalized value 与展示/写入值分开。

比较规范化：

- Unicode NFKC。
- 大小写折叠。
- 合并空白。
- 统一常见全角/半角标点。
- 去除不影响语义的包围标点。
- 简繁转换只能用于额外匹配通道，不能覆盖原名。
- 将 `feat.`、`ft.`、`Live`、`Remaster`、`Instrumental` 等提取为 token，但不无条件删除。

原始 provider 文本原样保留用于展示和用户选择。

艺术家：

- provider 返回结构化数组时按数组处理。
- 本地单字符串不得默认按逗号切分。
- artist credit 顺序有意义。
- “Various Artists”和单曲 artist 分开。

## 7. 评分

### 7.1 基础分

建议初始权重：

| 维度 | 权重 |
|---|---:|
| 标题相似度 | 0.35 |
| 艺术家相似度 | 0.25 |
| 专辑相似度 | 0.15 |
| 时长 | 0.15 |
| track/disc | 0.05 |
| 日期/版本 token | 0.05 |

实现可使用归一化 Levenshtein/Jaro-Winkler 与 token 相似度组合，但分数必须可解释，不只返回一个黑盒数值。

### 7.2 精确标识

- 相同 provider ID：1.0。
- MusicBrainz recording ID：1.0。
- ISRC 精确且 duration 合理：至少 0.98。
- 指纹高分并链接同一 recording：至少 0.97。

### 7.3 惩罚

- duration 相差 >15 秒或 >8%：显著扣分；>30 秒默认拒绝，除非版本 token 能解释。
- local 为 Live/Remix/Instrumental 而 candidate 不是，或反之：扣分/拒绝。
- 已有明确 artist 且完全不匹配：拒绝自动推荐。
- album/disc track 数量明显不一致：专辑匹配扣分。
- 同名不同语种、cover、karaoke、demo 需要显式版本 token。

### 7.4 分级

- `exact`：精确 ID。
- `high`：≥0.92，可进入“接受所有高置信”，仍需总确认。
- `review`：0.80–0.92，必须逐项审核。
- `low`：<0.80，默认折叠。
- `rejected`：触发硬冲突。

阈值放在服务端配置并记录算法版本。候选缓存中存 score components，算法升级后可以重算。

## 8. 多来源聚合与去重

流程：

```mermaid
flowchart LR
    Q["Local Track Query"] --> P["Enabled Providers<br/>parallel within limits"]
    P --> N["Normalize each result"]
    N --> D["Deduplicate"]
    D --> S["Score against local"]
    S --> C["Candidate list"]
    C --> F["Fetch selected details<br/>lyrics/artwork lazily"]
    F --> R["Field-level review"]
```

去重键优先级：

1. MusicBrainz Recording ID。
2. ISRC。
3. provider 间已知 ID mapping。
4. normalized title + artists + duration bucket。

不要过早把不同发行版本合并。相同 recording 的不同 release 可能有不同封面、日期、专辑名、音轨号。

Composite candidate：

- 基本结构来自用户选择的主候选。
- 歌词可来自 LRCLIB/网易云。
- 封面可来自 CAA/用户上传。
- 每个字段显示来源。
- 应用历史记录每字段 provenance。

## 9. 专辑匹配

专辑批量匹配不是“把专辑字段写给文件夹中所有文件”。

步骤：

1. 从目录/选择集构建 LocalAlbum，保留每首 title、artist、duration、track/disc。
2. 搜索 AlbumCandidate，获取完整 tracklist。
3. 建立本地曲目与候选 track 的匹配矩阵。
4. 优先 track+disc 精确，再使用 title/artist/duration。
5. 生成一对一分配；不能让两个本地文件匹配同一候选 track。
6. 计算 coverage、平均分、未匹配本地文件和缺失候选 track。
7. 高置信也必须展示 bonus track/隐藏 track/多 disc 差异。

MVP 可以先采用确定性贪心匹配；P1 再引入最大权重二分匹配。任何没有 title 且没有可靠 track number 的文件默认跳过。

专辑 artist 只能写 `AlbumArtists`；每曲 `Artists` 必须来自该曲目候选或保持本地值。

## 10. 字段应用策略

内置策略模板：

### `missing_only`

- 只填写当前空字段。
- 不删除、不覆盖。
- 最安全，批量抓取默认。

### `selected_fields`

- 只修改用户勾选字段。
- 候选空值仍然 Keep。

### `replace_common`

- 替换标题、艺术家、专辑、专辑艺术家、track/disc、date。
- 保留评论、自定义标签、ReplayGain 和未知标签。

### `exact_mirror`

- 高级模式，按候选覆盖选定规范化字段。
- 仍不清空 Extra/未知标签。
- 需要二次确认。

封面和歌词永远有独立 toggle，不被普通“全部字段”隐式选中。

## 11. HTTP、缓存与韧性

每个 provider 拥有：

- 独立 `http.Client`/transport policy。
- connect/TLS/header/body 总 deadline。
- limiter 和最大并发 semaphore。
- cache namespace 与 schema version。
- circuit health 统计，但不做永久熔断。

重试：

- 只重试幂等 GET/查询。
- 网络瞬断、429、502/503/504 可重试。
- 尊重 Retry-After。
- 指数退避 + jitter，有最大次数和总时长。
- 4xx 配置/认证错误不盲目重试。

缓存建议：

| 内容 | TTL |
|---|---|
| 文本搜索 | 1–6 小时 |
| ID 详情 | 7–30 天 |
| MusicBrainz/CAA not found | 1 小时 |
| LRCLIB not found | 1–7 天；允许手动 force refresh |
| provider 认证失败 | 不缓存业务结果 |
| 图片二进制 | 只在用户预览/应用时短期缓存 |

缓存键包含 provider、adapter schema version、storefront/locale、规范化 query。缓存负结果时保留错误类型，不能把超时缓存成“无结果”。

## 12. 配置与健康检查

`Descriptor` 还应提供配置 schema：

```go
type ConfigField struct {
    Key       string
    Label     string
    Type      string
    Required  bool
    Secret    bool
    HelpURL   string
}
```

健康状态：

- `ready`：配置有效且最近测试成功。
- `degraded`：可用但出现限流/部分 endpoint 失败。
- `misconfigured`：缺少 token/cookie。
- `disabled`。
- `unknown`：尚未测试。

测试连接是显式轻量请求，不在每次打开设置页时消耗配额。

## 13. 新增一个 provider 的流程

1. 新建 `internal/providers/<id>`。
2. 实现 `Provider` 和实际支持的小能力接口。
3. 定义配置 schema、限流和用途政策。
4. 将远程 schema 映射到统一候选模型。
5. 添加响应 fixture、golden test、超时/429/空字段测试。
6. 注册到 registry。
7. 更新能力矩阵和设置页文案。
8. 通过“单源失败不影响聚合”的集成测试。
9. 若为非官方接口，默认 Experimental/disabled。

## 14. 指纹扩展

[AcoustID](https://acoustid.org/webservice) 可以通过 Chromaprint 指纹返回关联的 MusicBrainz recording。限制：

- 官方 Chromaprint 是 C/C++，Go binding 通常需要 CGO。
- `fpcalc` 依赖额外可执行文件和音频解码能力。
- 这与核心单二进制、易交叉编译目标存在冲突。

因此：

- 接口从第一版预留。
- MVP 不内建计算。
- P2 可检测系统 `fpcalc`，作为可选 helper；未安装时功能隐藏。
- 若未来嵌入目标平台 helper，需要单独评估许可证、供应链、提取目录和多架构发布，不影响无指纹的主程序。
- 指纹只上传指纹和时长，不上传音乐文件。

## 15. 抓取器验收基线

- 同一查询可并发请求多个 provider，但严格遵守每源 limiter。
- 一个 provider 超时不阻塞其他结果超过聚合总 deadline。
- 所有候选保留 provider ID、external ID、原始 URL 和字段来源。
- 评分返回各维度贡献和拒绝原因。
- 同一 recording 的不同 release 不被误合并。
- 429 正确使用 Retry-After，任务转 `waiting_retry`。
- 超时/5xx 不被缓存成 not found。
- secret 不出现在日志、错误、SSE 和诊断导出中。
- 网易云/酷我关闭时没有任何网络请求。
- Apple/iTunes 封面根据 UsagePolicy 决定能否进入“写入文件”选项。
- 批量抓取完成后只是 `review_required`，没有未经确认的文件写入。
