# 跨源智能匹配与 AI 筛选

> 设计与首版实现基线：2026-09-01，代码基线 `654ce04`

## 1. 目标与边界

“智能选择”不是固定的 Apple、MusicBrainz、LRCLIB 组合，也不是一个新的远端数据源。它消费用户本次允许的全部已启用 Provider 结果，将同一录音和同一发行版本的候选聚合后，生成一个可审计的复合候选。

必须满足以下边界：

1. 原始 Provider 候选完整保留，用户始终可以绕过智能建议。
2. 每个字段都能追溯到真实 Provider、候选 ID 和外部 ID。
3. 数据源失败只降低证据覆盖，不使整首曲目失败。
4. 缺少歌词或封面不降低“是不是同一首录音”的身份置信度。
5. 智能匹配只在 Provider 查询完成后执行，不绕过来源代理、缓存和 source-wide Gate。
6. AI 只能选择已有候选实体或放弃，不能生成标签值、歌词、图片 URL 或外部 ID。

## 2. 分层流程

```text
内嵌标签 / 路径提示 / 已有稳定 ID
                  ↓
           Provider 查询假设
                  ↓
        全部已启用来源的原始候选
                  ↓
    Recording 聚类：判断是否为同一录音
                  ↓
      Release 聚类：判断具体发行版本
                  ↓
     按字段选择值、确认来源和置信度
                  ↓
              智能选择
                  ↓
        可选 AI 选择 / 复核 / 放弃
```

Provider 注册表只负责获取数据。智能选择不注册为 Strategy，也不会拥有 Provider 代理或限流配置。智能候选的封面引用保留真实 Provider ID，下载时继续走该来源的 Gate 和代理。

## 3. 查询与文件名假设

文件名不能被一次性判定为“歌手在左”或“标题在左”。扫描器保留多种假设，并且不会把路径猜测直接提升为内嵌标签：

- 去除 `01 -`、`CD1 07 -` 等音轨前缀。
- 支持半角连字符、en dash 和 em dash。
- 同时保留 `title-artist` 与 `artist-title` 两种解释。
- 路径提示只在真实标签不完整时扩展 Provider 查询，避免批量任务无条件放大远端请求。
- ISRC、MusicBrainz ID、AcoustID 和指纹作为匹配证据随查询传入，但不会被模糊生成。

后续增强采用两阶段回退：先查内嵌标签；当结果为空、低置信或候选差距过小时，再查询与标签明显不同的文件名假设。

## 4. Recording 聚类

聚类强度按以下顺序判断：

1. MusicBrainz Recording ID、ISRC、AcoustID 或指纹一致。
2. 标准化标题、艺术家集合、时长和版本标记共同相似。
3. `Live`、`Remix`、`Acoustic`、`Instrumental`、`Remaster`、`Cover` 等互斥版本不得合并。
4. 两侧都存在且不一致的稳定 ID 是硬冲突。
5. 明显时长差异在没有稳定 ID 支撑时拒绝合并。

来源一致性按 Provider 去重。`LrcApi` 之类的聚合适配器可以贡献字段，但不会被计为自动接受所需的独立来源。

## 5. Release 聚类

Recording 内部继续根据以下证据选择发行版本：

- MusicBrainz Release ID。
- 专辑名和专辑艺术家。
- 年份。
- Track/Disc 编号。
- 本地查询中已有的专辑或 Release ID。

专辑、专辑艺术家、年份、Track/Disc 和 Release ID 只能从被选中的 Release 聚类中获取。算法不会使用跨发行版本的简单多数票，因此精选集出现次数更多时也不能覆盖本地明确指定的原专辑。

## 6. 字段融合

每个 `Field<T>` 保存：

- 最终值。
- 主来源名称。
- 支持该值的来源引用。
- 字段置信度。
- 是否为推导值。

选择规则：

| 字段 | 范围 | 规则 |
|---|---|---|
| 标题、艺术家、时长 | Recording | 归一化值共识，保留最高质量来源的展示格式 |
| 专辑、专辑艺术家、年份、音轨/光盘 | Release | 只在选定发行聚类中选择 |
| 歌词 | Recording | 优先有效同步歌词，再比较匹配度与内容完整性 |
| 封面 | Release 优先 | 优先选中发行版本中的封面，缺失时才退回同一录音的其他来源 |
| ISRC、MBID、AcoustID | Recording/Release | 只采用来源明确返回的值 |
| Genre | Release | 归一化去重后合并，保留所有贡献来源 |

缺失 Album Artist 不再静默伪装成来源返回的 Track Artist；如果未来启用推导，必须设置 `derived=true`。

## 7. 评分与自动接受

匹配证据拆为：

- `identityScore`：同一录音的概率。
- `releaseScore`：同一发行版本的概率。
- `completenessScore`：候选字段覆盖。
- `assetQuality`：歌词与封面可用性。
- `margin`：最佳 Recording 聚类与第二名差距。
- `conflicts`：稳定 ID、版本或时长冲突。

首版自动接受条件：

- 身份分不低于 `0.94`。
- 与第二聚类分差不低于 `0.08`。
- 没有硬冲突。
- 至少两个非聚合独立来源，或存在本地稳定 ID 的明确匹配。
- 标题和艺术家均可用。

自动接受只表示审核页默认进入“已接受”状态，不会自动写文件。实际写入仍需用户创建写入任务。

## 8. AI 筛选契约

AI 是智能选择之后的可选裁决层，建议只在以下情况运行：

- 最佳与第二名差距不足。
- 文件名的歌手/标题方向存在歧义。
- 音译、别名或多语言标题使规则相似度不稳定。
- 同一录音存在多个相近发行版本。
- 用户主动请求 AI 复核。

AI 输入只包含查询摘要、聚类 ID、候选摘要、时长、版本标记和冲突。输出必须满足固定 Schema：

```json
{
  "decision": "select | abstain",
  "recordingClusterId": "rec-...",
  "releaseClusterId": "rel-...",
  "confidence": 0.0,
  "reasonCodes": []
}
```

模型不能返回请求之外的 ID。AI 与智能选择一致时只显示“AI 复核一致”；不一致时生成独立 AI 候选并强制人工确认。模型未配置、超时或输出非法时保留智能候选，不使曲目或批次失败。

首版代码只保留 `ai` 候选类型和明确的未配置状态，不连接任何外部模型；接入前必须先确定模型供应商、密钥存储、隐私范围、调用成本和超时策略。

## 9. 分阶段实施与验收

### 阶段 A：模型与规则基础

- 候选增加 `source | smart | ai` 类型。
- 字段增加多来源与置信度。
- 拆分身份、发行、完整度、资源质量和分差。
- 移除“没有封面就压低身份分”的逻辑。

### 阶段 B：智能选择首版

- 所有已启用 Provider 进入候选池。
- Recording/Release 两级聚类。
- 字段级融合、智能封面引用和历史来源。
- 服务端决定推荐与自动接受，前端不再自行使用单一分数阈值。

### 阶段 C：审核体验

- 候选按“推荐方案 / 原始数据源”分组。
- 智能候选显示来源数、原因、分差和冲突。
- 差异表逐字段显示真实来源。
- AI 未配置状态显式展示，不伪造 AI 结果。

### 阶段 D：批量专辑上下文

- 对同目录文件和远端 Release 曲目建立代价矩阵。
- 使用 Hungarian/Jonker–Volgenant 做一对一分配。
- 增加专辑覆盖率和最差单轨守门条件。

### 阶段 E：指纹与 AI

- 文本低置信时按需运行 Chromaprint/AcoustID。
- 接入严格 Schema 的 AI Selector、缓存、超时、审计和隐私设置。
- AI 初期禁止自动接受，先通过用户选择记录做影子评估。

主要指标是错误自动接受率，其次才是自动覆盖率。同时记录 Top-1 Recording 准确率、Release 准确率、字段采纳率、每曲 Provider 请求数、P95 延迟和 AI 调用率。
