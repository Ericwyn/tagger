# 持久化批量编辑任务

验证日期：2026-08-20

## API 与任务模型

- `POST /api/v1/tracks/batch-edit`：提交曲目 ID、基准 revision、公共字段操作和顺序编号选项，立即返回 `batch_edit` job。
- `GET /api/v1/jobs/:id/batch-edit-items`：读取每个文件的 `written`/`failed` 状态、错误和字段 diff。
- `POST /api/v1/jobs/:id/retry`：只重试失败 item，并在重试请求时读取当前曲目 revision，避免旧 revision 覆盖外部修改。

允许的字段是专辑、专辑艺术家、年份和风格；操作类型为 set/append/delete。顺序编号作为显式选项写入音轨号和总音轨数。服务端再次校验字段、操作、重复曲目和存在性，不信任前端 payload。

## Worker

worker 对每首曲目独立构造 `domain.TagPatch`，调用现有安全 writer；成功后重新扫描并写入“批量编辑标签” revision，失败只更新该 item，任务最终为 `partial`。SQLite 的 job 状态、item 结果和 revision 审计均可在服务重启后恢复。

## 测试

- Server 测试覆盖 202 入队、基准 revision 注入和非法操作拒绝。
- Store 测试覆盖 batch_edit item 独立状态持久化。
- Main 测试覆盖 set/append/delete patch 构造与顺序音轨生成。
- 前端 API 测试覆盖 batch_edit payload 和真实 endpoint；面板测试覆盖操作/预览。

## 边界

当前批量编辑仍不支持文本查找替换、CSV/JSON 导出和独立 item SSE；任务中心的 job SSE 与 item GET 快照作为可靠兜底。
