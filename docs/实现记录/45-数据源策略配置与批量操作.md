# 数据源策略配置与批量操作

> 日期：2026-08-20

## 背景

设置页原来的“配置”按钮没有实际行为，批量补全也只显示“正在整理候选结果”，批量封面只能上传本地文件。本次把这三条链路接到真实的策略、任务和文件 API。

## 数据源配置

数据源仍然使用 `providers.Strategy` 策略接口；需要暴露运行时配置的策略额外实现 `providers.Configurable`：

```go
type Configurable interface {
    ConfigFields() []ConfigField
    Configure(map[string]string) error
}
```

当前内置策略都声明自己的字段，例如：

- MusicBrainz、LRCLIB、Apple：API URL、User-Agent、地区或限流间隔；MusicBrainz 还可单独配置 Internet Archive 封面下载基址；
- 网易云、酷我、酷狗：搜索/歌词/封面端点、User-Agent、限流间隔和可选 Authorization；
- LrcApi：歌词 API、封面 API、User-Agent、限流间隔和可选 Authorization。

`Registry` 负责字段白名单校验、调用策略的 `Configure`、保存配置和返回描述。配置存储复用 `provider_settings.config_json`，启动时加载并应用，因此修改后不需要重启。密码/令牌字段只返回 `configured` 状态，不返回明文；当前 SQLite 仍是本机配置存储，敏感配置加密列入后续任务。

HTTP API：

```http
PATCH /api/v1/providers/:id
Content-Type: application/json

{"config":{"baseUrl":"https://mirror.example/api","auth":"Bearer …"}}
```

前端使用策略返回的 schema 动态绘制浮动配置面板，空密码表示保持原值；测试查询单独保留在诊断面板中。

## 批量补全进度

匹配 worker 每处理一首曲目都会更新任务详情：

```text
已分析 3/24 首曲目 · 已查询 9 次数据源 · 返回 14 个候选
```

任务中心继续使用 `processed/total` 进度条；审核页创建匹配任务后订阅同一个任务的 SSE，在候选尚未整理完成时显示曲目进度、累计数据源查询次数和候选数量，完成后自动加载审核快照。

## 批量复用嵌入封面

批量编辑的封面来源现在有两种：

1. 从本地选择图片；
2. 从本次选中的曲目中选择一首有嵌入封面的歌曲。

第二种方式通过 `GET /api/v1/tracks/:id/artwork/0?revision=...` 读取真实二进制，前端转成批量任务的 base64 载荷；后端仍统一执行 MIME/尺寸校验、可选 1000×1000 或 500×500 居中裁剪、逐文件 revision 防护和历史记录。
