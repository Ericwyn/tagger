# 播放器、审核流与占位封面体验

验证日期：2026-08-20

## 本次完成

- 播放器从曲目 Inspector 中抽离到 App 根部，音频元素只挂载一份；切换曲库、任务、历史和设置页面时不再因页面卸载而暂停。
- 审核页的“跳过此曲”和“接受候选”会更新当前项状态并自动跳到下一首；“更换候选”会循环候选并重置可用字段。
- 真实模式创建写入任务时，将已接受匹配项写为 `write_pending`，并保存 `selectedCandidateId`，任务中心可以继续显示后续写入结果。
- 任务中心状态 Tab 已接入过滤逻辑：全部、进行中、待审核、失败/部分失败。
- 设置页新增生成式封面占位开关，默认关闭；关闭时无真实图片统一显示空白占位。候选远程封面尚未下载前也保持空白，避免把 provider 的 `hasArtwork` 标志误当成已展示的图片。
- 候选查询支持编辑标题、艺术家、专辑后重新请求，查询仍携带原曲目 ID 作为上下文。

## 明确边界

审核页当前的跳过/接受草稿状态仍保存在前端内存；只有提交写入任务后，接受项的 `write_pending` 状态会落到 SQLite。刷新审核页后继续审核和持久化跳过状态列入后续任务。
