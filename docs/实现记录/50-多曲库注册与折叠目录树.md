# 多曲库注册与折叠目录树

## 已完成

- `libraries` 表本身作为独立曲库索引注册表，按根目录保存扫描摘要、报告和曲目数据；新增 `ListLibraries`、`LibraryByID`，由 `library_root` 设置计算当前活动曲库。
- 启动时 `--music-dir` / `TAGGER_MUSIC_DIR` 可以完全省略。程序会依次尝试恢复有效的活动根目录、旧版本数据库中最近扫描的根目录；都没有时使用数据目录下的私有空目录，让前端进入“尚未配置曲库”状态，而不是直接退出。
- `POST /api/v1/libraries` 先探测目录，再排队首轮扫描；扫描成功后才在注册表中出现。`GET /api/v1/libraries` 返回全部已扫描曲库并标记 `active`，设置页支持新增、重新扫描和切换。
- 曲库切换和添加共用任务保护：运行中或待审核任务存在时返回冲突，避免切换索引边界时修改目标文件。
- 侧栏将后端的扁平相对路径按 ` · ` 分隔重组成树，根目录默认展开，子目录默认折叠；父节点显示聚合曲目数，点击展开箭头不会改变当前筛选。

## 边界

- 当前仍是单用户、单活动曲库运行时模型；多个曲库的索引和配置独立保存，但一次只允许一个曲库作为浏览/写入目标。
- 新目录必须完成首次扫描后才会出现在已注册列表；扫描失败不会留下不可用注册项。
