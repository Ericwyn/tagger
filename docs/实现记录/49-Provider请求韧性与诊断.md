# Provider 请求韧性与诊断

## 本次范围

本次先补齐所有数据源共用的网络边界，不把任何一个实验性来源提升为唯一依赖，也不伪造“接口稳定”的状态。

- 幂等的 HTTP GET 最多尝试 3 次；网络瞬断、408、429 和 5xx 才会重试，配置/鉴权类 4xx 不会盲目重试。
- 重试等待使用短指数退避，并读取 `Retry-After`（秒或 HTTP-date）；等待受上限和请求 context 约束。
- Provider 响应仍受大小上限保护，错误响应正文只保留有限长度，避免把整段 HTML/代理错误页写入任务或日志。
- Kuwo 的 JSON、XML 和纯文本歌词请求，以及候选封面下载，复用同一安全重试和大小校验层。
- Kuwo 搜索会先使用歌曲+歌手/专辑关键词，结果为空时自动退回歌曲名；配置的鉴权头、Origin 和 Referer 会同时应用到搜索与歌词兼容接口。
- 同一 Provider、规范化查询和 limit 的冷缓存请求通过 singleflight 合并，避免批量任务同时命中同一首歌时重复打上游。

## 测试页行为

数据源测试遇到上游 429/5xx 或网络失败时仍返回结构化测试响应，不再只返回一个空的 HTTP 502。响应会保留：

- `status=error`、错误信息和是否可重试；
- `retryAfterMs`（如果上游给出等待建议）；
- `search` 阶段日志，便于判断是请求失败、无候选还是封面探测失败。

前端诊断浮动面板显示“可重试”和建议等待时间，候选为空时仍能查看日志。

## 边界与后续

这不等于网易云、酷我、酷狗接口已经获得官方授权或长期稳定保证。它们仍是默认关闭的实验性策略；后续仍需针对每个来源做授权配置、接口变更探测、字段回归样本和更准确的错误分类。

验证覆盖公共 HTTP 重试/`Retry-After`/传输错误、并发查询合并、Kuwo 歌词调用、封面下载和 Provider 测试失败日志；不依赖外网。
