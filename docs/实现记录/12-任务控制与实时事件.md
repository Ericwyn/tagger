# 任务取消、失败重试与实时事件

验证日期：2026-08-20

## 状态转换

任务队列新增 `cancelled` 终态。等待中的扫描、匹配和写入任务可以立即取消；运行中的任务使用子 context 协作取消，worker 收到取消后才落盘终态，避免在文件写入临界区强行中断。任务进入 `review` 后也可以取消，但已完成、部分完成和失败任务不能重复取消。

失败、部分完成或已取消任务可以重试。扫描任务重跑整个扫描；匹配任务重新提交 `failed`/`no_match` 以及取消前尚未生成 item 快照的曲目；写入任务重新提交 `write_failed`/`artwork_failed`/`write_pending` 及缺失快照，批量编辑任务重新提交 `failed`/`pending` 及缺失快照。成功项不会被重复覆盖，封面阶段失败仍只补封面并使用当前 revision。过滤后的 payload 会同步更新任务总数，重试进度从 `0 / 实际重试项数` 开始。

## API

- `POST /api/v1/jobs/:id/cancel`：协作取消任务。
- `POST /api/v1/jobs/:id/retry`：重置任务并重新入队；服务端按任务类型过滤失败 item。
- `GET /api/v1/jobs/:id/events`：单任务 SSE，事件数据是与 `GET /jobs/:id` 相同的 job 快照。

事件通知只在进程内保留，使用有界缓冲；慢客户端可能丢失中间进度，但不会丢失事实，因为前端会继续使用 GET 快照轮询和断线恢复。事件 ID 只用于本次连接内排序，暂不承诺跨重启回放。

## 前端

任务中心在真实后端模式订阅当前任务 SSE，同时保留 1 秒 GET 轮询作为兜底。运行中/等待中的任务显示“取消任务”，待审核任务额外提供“丢弃审核任务”（仍调用同一个 cancel API）；有失败项、未处理项或已取消的任务提供重试，纯后处理错误但没有可重试 item 时不显示误导按钮。失败/部分完成的匹配流程保留“打开审核页”。丢弃审核只删除候选审核快照，不修改音乐文件。

## 验收

- Manager 测试覆盖运行中协作取消、`cancelled` 终态、事件通知和失败任务重试。
- Server 测试覆盖等待任务取消，以及匹配任务只过滤失败曲目后的重试 payload。
- 前端 API 测试覆盖 cancel/retry URL 和 EventSource 生命周期。
- `go test -race ./internal/jobs ./internal/server` 通过。

## 后续边界

全局任务事件流、持久化事件表、取消原因/操作者和按 item 的细粒度 SSE 仍属于后续增强；当前 SSE 的设计目标是低复杂度实时刷新和可靠快照恢复。
