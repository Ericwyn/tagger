# 审核筛选、查询历史与重新匹配

## 本次完成

- 审核队列增加可用的状态筛选（待确认、已接受、已跳过）和候选来源筛选；筛选后右侧详情与当前队列保持一致。
- 候选抽屉按曲目保存最近 8 条查询条件，优先合并 SQLite 后端历史，浏览器本地存储作为离线/Mock 降级；历史项可以直接再次查询。
- 新增 `GET /api/v1/matches/tracks/:id/query-history`，每次成功的单曲搜索记录查询条件、指定来源、候选数量和时间。
- 新增 `POST /api/v1/matches/jobs/:id/items/:trackId/rematch`。重新匹配会在任务审核态下更新候选快照、清除旧字段选择/封面选择，并保留候选 ID 校验链路，之后可以正常接受并创建写入任务。
- 无候选曲目也提供“重新匹配此曲”入口，不需要退出审核页。

## 数据与兼容

- SQLite migration `00010_match_query_history` 新增查询历史表和按曲目时间索引。
- 查询历史写入失败不会阻断候选搜索；历史读取失败时仍使用浏览器本地记录。
- 重新匹配仅允许匹配任务处于 `review` 或 `partial` 状态，避免覆盖已进入写入流程的快照。

## 验证

- 前端 lint、54 个 Vitest 用例通过。
- Go 全量测试通过，覆盖重新匹配候选替换、查询历史写入和读取。
