# 运行时曲库切换

## 背景

此前音乐目录主要由启动参数 `--music-dir`/`TAGGER_MUSIC_DIR` 决定，设置页的目录探测只能检查候选目录，无法在不重启进程的情况下切换曲库。HTTP 监听地址仍然是启动参数，不能在运行中修改；本次只把音乐文件根目录作为受控的业务操作开放出来。

## 行为

1. 设置 → 音乐目录 → 验证目录会检查候选路径是否为真实目录，并统计音频格式、子目录、读写权限和警告。
2. 点击“切换到此目录”后，后端先检查任务队列。存在等待中、运行中或待审核任务时返回 `409 library_switch_busy`，避免审核快照或写入目标在换根后失效。
3. 通过探测的目录会进入一个 `scan` 后台任务。worker 先扫描或恢复该目录的持久化索引，成功后才同时替换活动 Scanner、曲库快照和安全写入器的根目录。
4. 扫描、索引持久化或写入边界校验失败时，旧曲库保持不变；任务失败原因可以在任务中心查看。
5. 活动根目录写入 SQLite `system_settings.library_root`，曲库 API 同时返回 `rootPath`（侧栏继续使用短的 `rootLabel`）。启动时如果没有显式提供 `--music-dir`，会恢复该值；首次启动仍需要通过参数提供目录，或在已有进程中从设置页选择目录。

## 安全边界

- 根目录和写入器都拒绝符号链接根目录、非目录路径以及越界相对路径。
- 切换 API 只接受当前活动曲库 ID，并通过目录探测再次校验路径，不接受客户端直接注入扫描结果。
- 切换期间使用现有扫描锁；任务中心的活动任务检查阻止并发切换。单用户模式下，建议先完成或取消任务再操作。
- 旧版 SQLite 扫描快照没有 `rootPath` 时，服务启动会用当前已验证的 Scanner 根目录补齐，不要求迁移旧音频索引。

## 验证

- `internal/library` 覆盖“新目录先扫描、成功后替换旧索引”和失败保持旧状态。
- `internal/filewrite` 覆盖写入器根目录切换后的边界校验。
- `internal/server` 覆盖目录探测、排队响应以及活动任务冲突。
