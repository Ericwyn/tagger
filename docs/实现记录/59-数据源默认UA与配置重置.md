# 数据源默认 UA 与配置重置

## 已完成

- 面向网易云、酷我、酷狗、LRCLIB、Apple/iTunes 和 LrcApi 的默认请求 UA 改为普通浏览器标识；酷狗移动接口使用移动浏览器标识。
- MusicBrainz 保留 `Tagger/0.1 (https://github.com/ericwyn/tagger)` 这一可联系应用标识，因为该官方 API 要求请求带应用名、版本和联系方式，并通过现有 1 req/s 限流。
- Provider 封面 CDN 下载统一使用浏览器 UA，不再发出 `Tagger/0.1` 标识；原有 Accept、HTTPS allowlist、重定向和图片字节校验保持不变。
- 旧版本 SQLite 中保存的内置 `Tagger/...` 默认 UA 会在启动加载配置时迁移为新的来源默认值；用户自行填写的非 Tagger UA 不会被覆盖。
- 每个内置 Provider 实现可选的运行时配置重置能力。新增 `POST /api/v1/providers/:id/reset`，清除 endpoint、UA、鉴权、Cookie、地区和限流等覆盖，但不改变启用状态。
- 设置页配置面板增加“恢复默认配置”二次确认操作，并在完成后刷新字段和敏感配置状态。

## 验证

- Go Provider 测试覆盖各来源默认 UA、重置后的默认 endpoint/UA、旧 UA 迁移和配置持久化清理。
- Server 测试覆盖 Provider reset HTTP 端点。
- 前端 API 测试覆盖 reset 请求，SettingsPage 测试覆盖二次确认和成功反馈。
