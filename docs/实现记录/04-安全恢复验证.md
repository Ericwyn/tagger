# 标签历史安全恢复验证

验证日期：2026-08-20

## 恢复语义

修订记录同时保存该次写入的 `before_tags` 和 `after_tags`。恢复 API 显式接受：

- `target=before`：恢复到这次修改发生之前，前端默认使用此模式，等价于审慎撤销该次修改。
- `target=after`：恢复到这次修改完成之后，供后续详情操作和重新应用使用。

API 分为两步：

1. `POST /api/v1/revisions/:id/restore-preview` 只读取当前文件并计算相对当前磁盘标签的 diff。
2. `POST /api/v1/revisions/:id/restore` 执行写入。

两步都要求请求体 `baseRevision` 与 `If-Match` 一致。前端从历史列表取得当前曲目的最新 revision；即使预览后文件又被外部程序或其他请求修改，执行阶段仍会返回 `409 revision_conflict`，不会盲目覆盖。

## 写入安全

恢复复用普通标签写入的同一条底层路径：

- 校验曲库 containment 并拒绝符号链接。
- 按文件加锁并重读当前标签计算 revision。
- 在音乐文件同目录建立临时副本。
- 只在副本上写入目标字段，重读并逐字段验证。
- `fsync` 后原子替换原文件并同步目录。
- 重新扫描并持久化当前曲目快照。
- 追加一条新的“恢复到修订前/后”审计记录，来源保存原修订 ID。

当前恢复范围是 Tagger 正式管理的标准字段：标题、艺术家、专辑、专辑艺术家、音轨/光盘号、年份、流派和歌词。未知标签与格式私有字段保持当前值，预览和执行响应都会明确返回这一 warning。这样不会为了追求不可靠的“全量还原”而删除 TagLib 无法保真表达的私有帧。

封面和 sidecar 尚未进入本轮恢复范围；加入内容寻址 blob 历史后再扩展同一两步协议。
