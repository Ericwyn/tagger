# 音乐目录探测

> 日期：2026-08-20

## 范围

当前单二进制的活动曲库仍由 `--music-dir` / `TAGGER_MUSIC_DIR` 决定，运行中的任务和写入器不会因为设置页输入路径而被替换。本次先把“添加目录”从无反馈按钮改为真实的目录探测流程，为后续动态多目录/切换建立安全边界。

## 后端

`POST /api/v1/libraries/probe` 接受 `{ "path": "..." }`，调用 `library.ProbeRoot`：

- 拒绝不存在路径、普通文件和符号链接根目录；
- 不跟随子目录符号链接，跳过隐藏目录和隐藏文件；
- 统计 MP3、FLAC、WAV 数量和子目录数量；
- 返回目录可读状态、权限位可写状态及遍历警告；
- 设置 20,000 项探测上限，避免远程调用拖垮进程；
- 只读探测，不写入数据库、不改变当前曲库。

## 前端

设置 → 音乐目录 → 验证目录打开浮动面板，展示路径、读写状态、格式统计和警告，并明确提示切换活动曲库仍需要启动参数和重启。Mock API 与真实 API 共用同一数据契约。

## 验证

- `ProbeRoot` 单元测试覆盖格式统计、权限、普通文件和符号链接拒绝；
- Server API 测试覆盖成功和失败响应；
- `TAGGER_TEST_MUSIC_DIR=/home/ericwyn/Downloads/TestMusic make test-integration` 新增真实 TestMusic 探测用例。

动态多目录注册、运行中切换和每目录 ACL 仍保留在后续主线，避免在后台任务运行时替换扫描器/写入器造成文件边界不一致。
