# fsnotify 优先的实时曲库索引

曲库浏览现在把文件存在性与标签元数据拆成两层。`fsnotify` 事件先对受影响目录执行轻量文件清单对账，新文件和外部变化文件立即以 `draft` 状态进入列表；后台定向扫描只读取这些文件的标签，完成后通过曲库 SSE 通知页面刷新。SQLite 的 `library_files` 保存相对路径、文件指纹、存在状态和同步状态，原 `tracks` 数据继续作为元数据缓存。

监听任务使用独立的繁忙判断，待审核任务不再阻止文件变化进入索引；扫描和写入期间的事件仍会合并并重试。缺失文件默认从普通浏览隐藏，但保留缺失索引和历史供显式筛选、清理。

新增 `--watch-mode` / `TAGGER_WATCH_MODE`：`auto` 默认优先事件监听，初始化或运行错误后进入降级轮询；`events` 使用事件模式；`poll` 显式使用轮询。监听健康时前端只在进入目录或窗口聚焦时校验一次，降级/轮询状态才会在页面可见期间每 5 秒读取当前目录。
