# 审核状态持久化

验证日期：2026-08-20

## 本次完成

- 新增 `PATCH /api/v1/matches/jobs/:jobId/items/:trackId`，接受 `review`、`accepted`、`skipped` 和选中的 candidate ID。
- 审核页真实模式下的接受、跳过、更换候选和“接受所有高置信”都会更新 SQLite 匹配项。
- 任务中心打开审核页时传递原匹配任务 ID；页面不再重新创建一批候选，直接读取已有匹配结果和审核状态。
- 接受候选后创建写入任务，后端继续把匹配项推进为 `write_pending`，写入 worker 成功/失败状态不受影响。
- candidate ID 会在服务端按该曲目的候选列表校验，不能提交其他曲目的候选。

## 边界

字段 checkbox 的临时选择尚未单独持久化；重新打开任务时会按选中候选的可用字段重新初始化，最终写入前仍可调整。后续若需要跨设备协作，再增加审核选择快照字段和迁移。

- Go 全量测试通过，server 测试覆盖接受、跳过、候选 ID 校验和 `write_pending` 推进。
