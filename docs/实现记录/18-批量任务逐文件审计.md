# 批量任务逐文件审计

验证日期：2026-08-20

## 前端闭环

任务中心对 `batch_edit` job 读取 `GET /api/v1/jobs/:id/batch-edit-items`，并在真实模式每秒刷新：

- 逐文件显示当前状态（等待中、已写入、失败）。
- 显示后端返回的错误原因，便于确认 revision 冲突或文件不可写。
- 将字段 diff 显示为“修改前 → 修改后”，数组字段使用多值分隔。
- 通过现有曲目列表把 track ID 映射为文件名；服务重启或 SSE 丢事件时仍以 GET 快照刷新。

Mock 模式不伪造持久化 item，显示明确的等待快照提示。

## 测试

- Real API 测试覆盖 batch item endpoint 和 URL 编码。
- 全部前端测试覆盖仍保持通过；Go 后端的 batch item store/API/worker 测试继续作为事实源。

## 边界

当前 item 快照按任务轮询，不提供独立 item SSE；大曲库页面会复用已有 `/tracks` 列表映射文件名，后续可改成服务端在 item 中持久化展示字段。
