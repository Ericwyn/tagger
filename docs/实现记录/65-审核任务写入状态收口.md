# 审核任务写入状态收口

## 问题

抓取任务完成后会进入 `review`，审核确认时另外创建一个写入任务。此前写入 worker 只更新匹配项的 `write_pending` / `written` 状态和写入任务自身，父抓取任务没有任何后续状态同步，因此任务中心会一直显示“待审核”。

## 实现

- 为持久化任务管理器增加带事件通知的外部状态更新入口，保证任务中心的 SSE 和轮询都能看到父任务变化。
- 在创建写入任务前先把匹配项标记为 `write_pending`，避免快速 worker 在请求回写审核快照时把已经完成的 `written` 状态覆盖掉；入队失败会恢复原快照。
- 写入 worker 完成后检查父匹配任务的所有匹配项：
  - `written`、`skipped` 和既有失败项均为终态时，父任务进入 `succeeded` 或 `partial`；
  - 仍存在 `review`、`accepted`、`write_pending` 或未知状态时，父任务继续保持待审核；
  - 写入失败、封面写入失败、抓取无匹配等会保留失败计数并进入部分完成。
- 父任务详情会显示已写入和跳过的曲目数量；实际文件写入进度仍以独立的安全写入任务为准。
- 增加成功收口和仍有待审核项时保持打开的 Go 回归测试。
