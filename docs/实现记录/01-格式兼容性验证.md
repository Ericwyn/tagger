## 写入验证

所有写入均发生在临时目录，不修改原始语料。

| 格式 | 语料 | 验证内容 | 结果 |
|---|---|---|---|
| MP3 | 从 TestMusic 复制 | 标题设置、歌词删除、重读、原子替换、未提及标签与封面保持 | 通过 |
| FLAC | 从 TestMusic 复制 | 标题设置、歌词删除、重读、原子替换、未提及标签与封面保持 | 通过 |
| WAV | 测试现场生成 PCM WAV | 标题/艺术家设置、重读、容器与 PCM 属性保持 | 通过 |

端到端 HTTP 验证使用 `/tmp` 中的 MP3 副本：

1. 获取曲目及 revision。
2. `PATCH /api/v1/tracks/:id/tags` 修改标题。
3. 服务在同目录临时副本上写入并重读验证。
4. 原子替换后重新扫描，返回新标题和新 revision。
5. 使用旧 revision 再次提交，服务返回 HTTP 409 `revision_conflict`。
6. 目录内没有残留 `.tagger-*` 临时文件。
7. 前端编辑、diff 确认、保存、列表与检查器刷新完整通过，浏览器控制台无错误。

## 当前结论

- MP3、FLAC 可进入 A 级读写实现阶段。
- WAV 的基础 RIFF/PCM 常用字段读写已经通过，但不同播放器对 RIFF INFO/ID3 chunk 的互操作仍需独立验证，因此产品等级暂维持 B。
- 写入 API 已具备路径 containment、符号链接拒绝、每文件互斥、revision 检查、同目录临时副本、写后验证、fsync 和原子替换。
- SQLite 修订历史、恢复、崩溃后的临时文件清理和 Windows 替换语义仍属于后续工作。
