# 嵌入封面安全读写验证

验证日期：2026-08-20

## 已实现能力

- `GET /api/v1/tracks/:id/artwork/:index` 读取真实嵌入图片，返回实际 MIME、内容 hash、尺寸和基于曲目 revision 的 ETag。
- `PUT /api/v1/tracks/:id/artwork/:index` 使用原始图片 body 替换/新增嵌入封面。
- `DELETE /api/v1/tracks/:id/artwork/:index` 删除指定嵌入图片。
- 写入和删除都要求 `If-Match`，旧 revision 返回 409。
- 前端曲目列表与检查器展示真实封面；封面页支持本地上传、在线查找入口和两次点击确认删除。
- 上传/删除成功后刷新曲目 revision、封面数量与健康状态，并创建“替换封面/删除封面”修订记录。

当前 UI 正式管理 index 0（Front Cover）；后端为后续多图界面保留 0–31 的受限 index。

## 图片安全校验

上传数据不信任扩展名或声明的 Content-Type。后端执行：

1. body 硬上限 10 MiB。
2. 使用文件签名检测实际 MIME。
3. 只接受 JPEG、PNG、WebP。
4. 声明 MIME 与实际 MIME 不一致时拒绝。
5. 使用真实解码器读取尺寸，拒绝无法解码的内容。
6. 拒绝超过 40MP 或非法尺寸的图片。
7. 计算 SHA-256，供响应、审计 diff 与后续 blob 去重使用。

前端 `accept` 只是用户体验提示，安全边界完全在 Go 后端。

## 文件写入安全

TagLib-WASM 原生支持 complex picture property，因此没有新增 CGO、FFmpeg 或系统 TagLib 依赖。封面写入复用标签写入的安全约束：

- 曲库 containment 与符号链接拒绝。
- 每文件互斥锁与 revision 重读。
- 同目录完整临时副本。
- 只修改副本中的图片。
- 从副本重读图片字节与图片数量；替换要求字节完全一致，删除要求数量准确减少。
- `fsync`、原子 rename、目录同步。
- 重新扫描后再更新 SQLite 索引和追加审计修订。

图片读取响应带 `nosniff`；前端 URL 包含当前 revision，可以对不可变版本使用长缓存而不会显示旧图。

## 格式兼容验证

| 格式 | 语料 | 替换 PNG | 重读 hash/尺寸 | 删除 | 时长保持 |
|---|---|---:|---:|---:|---:|
| MP3 | `TestMusic` 临时副本 | 通过 | 通过 | 通过 | 通过 |
| FLAC | `TestMusic` 临时副本 | 通过 | 通过 | 通过 | 通过 |
| WAV | 测试生成 PCM WAV | 通过 | 通过 | 通过 | 通过 |

真实 API 集成测试还覆盖图片响应 MIME/尺寸/字节、上传和删除历史、SQLite 重开后的审计记录和最终 `artworkCount=0`。原始测试音乐始终不被修改。

生产构建的浏览器验收确认：曲目表、检查器头部和封面页共加载 3 个真实图片节点；通过文件选择器上传 300×300 JPEG 后成功通知出现，API 重读字节的 SHA-256 与上传文件完全一致；历史页把原 1200×1200 / 496 KB 封面和新 300×300 / 18 KB 封面的 hash 摘要正确展示。删除按钮第一次点击只进入“再次点击确认删除”状态，不会立刻删除。

## 当前边界

- 修订 diff 已保存图片 hash 和尺寸，但图片二进制 blob 尚未写入内容寻址历史，因此当前标签恢复不会恢复旧封面。
- Provider 候选已提供封面 URL，但安全下载、SSRF 防护和应用按钮尚未接通。
- UI 当前只编辑第一张 Front Cover，多图类型/描述编辑随后补齐。
