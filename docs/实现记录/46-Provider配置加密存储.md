# Provider 配置加密存储

> 日期：2026-08-20

## 目标

数据源配置现在支持 API 地址、User-Agent、鉴权头和限流策略。鉴权头属于敏感信息，不能继续以明文放在 SQLite 的 `provider_settings.config_json` 中。

## 实现

- `Store.Open` 在数据目录生成 `.tagger-secrets.key`，使用 32 字节随机密钥，文件权限固定为 `0600`；已有密钥会复用，避免重启后无法解密。
- Provider 配置序列化为 JSON 后使用 AES-GCM 加密，数据库值带 `enc:v1:` 版本前缀，便于未来轮换格式。
- 启动读取时仍兼容旧版 JSON 明文行，成功解析后立即重写为加密载荷。
- 解密失败会阻止存储层启动并返回明确错误，不会把配置静默当成空值继续运行。
- API/前端的 secret 字段仍只展示 `configured` 状态，密钥不会回传浏览器。

## 边界

本机密钥与 SQLite 数据库放在同一数据目录，目标是防止数据库被误读或备份时直接暴露明文；如果攻击者同时取得密钥文件和数据库，仍需要操作系统文件权限或磁盘加密保护。密钥轮换和多用户权限控制继续列在后续主线。

## 测试

- AES-GCM 加解密往返和密钥文件权限测试；
- 旧版明文 `config_json` 自动迁移测试；
- Go Provider、Store、Server 回归测试继续通过。
