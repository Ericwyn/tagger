# 历史恢复预览空数组兼容

## 问题

封面或仅 sidecar 的恢复预览没有标签字段时，Go 的 `filewrite.Result` 可能把 `warnings`/`diff` 序列化为 `null`。历史页直接对 `warnings` 调用 `.map()`，因此点击“恢复到修改前”会出现白屏。旧数据库快照中的 `fields`、`diff` 也可能是 `null`。

## 实现

- 后端在仅资产恢复分支初始化空的 `diff` 和 `warnings` 数组。
- 历史响应和 SQLite 快照读取统一把 `fields`、`diff`、标签 map 归一化为非空容器。
- 前端真实 API 对历史记录和恢复预览做兼容归一化；历史页面渲染层也保留数组兜底，避免异常旧数据再次造成白屏。
- 增加真实 API、历史页面和 Go 历史响应回归测试，覆盖 `null` 的历史数组和恢复预览警告。
