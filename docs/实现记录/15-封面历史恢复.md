# 封面历史恢复

验证日期：2026-08-20

## 存储模型

Migration v6 新增 `artwork_blobs` 内容寻址表，并给 `revisions` 增加 `before_artwork_hash` / `after_artwork_hash`。相同图片只保存一次；revision 写入和 blob 引用在同一 SQLite transaction 中提交。列表读取只加载 hash，真正读取单条 revision 时才加载图片字节，避免历史页一次性读入所有大图。

## 恢复流程

对于包含 `artwork` diff 的修订：

1. 读取并校验当前文件 revision。
2. 先生成/执行标准标签恢复。
3. 以标签恢复后的新 revision 调用安全 `WriteArtwork`，恢复目标前/后的封面，目标为空时安全删除。
4. 合并标签与封面 diff，重新扫描并生成新的审计 revision。

预览阶段不会写文件，仍返回相对当前磁盘状态的完整差异。任何 revision 冲突都会在写入前返回 409。

## 验证

- Store 测试覆盖相同 hash 的 blob 去重和 revision 读取时字节 hydrate。
- History UI 测试覆盖封面-only 修订可以生成恢复预览。
- TestMusic MP3 临时副本集成测试覆盖 4×3 封面恢复为 2×2、重新读取 MIME/尺寸、随后删除，以及服务重开后的 6 条审计历史。

## 边界

当前仍管理 Front Cover index 0；多图封面类型/描述编辑和 blob 垃圾回收属于后续增强。blob 由历史 revision 引用，后续删除历史时需要同步引用计数或 mark-and-sweep。
