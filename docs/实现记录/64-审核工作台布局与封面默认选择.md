# 审核工作台布局与封面默认选择

## 背景

原审核页把保存和确认写入放在页面底部，右侧详情较长时需要反复滚动才能操作；左侧当前项只有很弱的背景变化，不利于连续审核。候选有封面但本地文件没有嵌入封面时，也没有给出合理的默认写入选择。

## 本次实现

- 将“接受所有高置信”“保存草稿并返回”“确认并创建写入任务”集中到顶部筛选工具栏，并保留写入错误提示。
- 在右侧详情增加吸顶的当前曲目操作栏，滚动字段差异时仍可直接跳过、更换候选或接受候选。
- 将左右区域保持为独立滚动容器，缩短审核页头部留白；移动端将操作按钮压缩为可读的三列布局。
- 当前曲目增加高对比背景、左侧色带和边框，候选状态标签同步加强边界色，便于在长列表中定位。
- 为审核条目记录 `artworkTouched`：首次进入时，如果本地 `artworkCount` 为 0 且候选声明有封面，则默认勾选“替换封面”；用户主动取消、调整尺寸或切换候选后保留用户选择。
- 增加前端回归测试，覆盖无本地封面时的默认勾选行为。

## 验证

- `npm run lint`
- `npm test -- --run`（17 个测试文件，110 个测试通过）
- `npm run build`
