# v1.1.0 发布说明

v1.1.0 主要改善两件事：让曲库整理更安全、更容易确认；让来自不同数据源的中文信息可以按需统一为简体中文。

## 更安全的曲库整理

歌曲列表现在可以直接发起文件整理。系统会先生成完整预览，展示整理根目录、原路径和目标路径，确认后再创建后台任务。整理只调整文件位置，不修改原文件名、音频内容或标签。

整理支持两种常用布局：

- `第一歌手 / 专辑 / 原文件名`
- `第一歌手 / 原文件名`

多歌手歌曲使用第一位歌手作为目录名，并保留原文件名。配套的 `.lrc` 歌词文件会随音频一起移动。目标冲突、无效路径、路径越界和不安全文件会在预览阶段拦截，任务执行前还会检查曲目版本，避免整理过期数据。

整理路径会跟随当前浏览位置：如果正在 `M` 目录中整理，目标会从 `M` 开始，例如 `M/歌手/专辑/原文件名`；从曲库根目录整理时，行为仍然是 `歌手/专辑/原文件名`。

## 可选的简体中文输出

数据源设置中新增“自动转为简体”开关。开启后，数据源在输出候选和歌词前会统一转换中文文本，覆盖歌曲名、歌手、专辑、风格以及普通歌词和带时间戳歌词等内容。

该选项已支持 Apple Music、MusicBrainz、LRCLIB、LrcApi、网易云、酷狗和酷我，并按数据源独立保存，默认关闭。关闭时不会改变现有结果；切换开关后也会使用对应的缓存版本，不会混用简体和繁体结果。

## 使用建议

第一次整理文件时，建议先在当前目录选择少量歌曲查看预览，确认目标路径和整理层级后再创建任务。需要统一中文显示时，可在“设置 → 数据源”中只为需要的数据源开启简体转换。

## 验证

本版本已通过 Go 全量测试、`go vet ./...`、前端全量测试、TypeScript 检查和生产构建，并完成曲库子目录整理预览验证；验证过程中未执行真实文件移动。
