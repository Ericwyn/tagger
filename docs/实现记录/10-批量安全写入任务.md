# 批量安全写入任务

验证日期：2026-08-20

## 流程

审核完成后，前端提交候选 ID、字段集合和每首曲目的基准 revision 到 `POST /api/v1/matches/jobs/:id/write`。后端只接受已持久化 match job 中的候选，不信任客户端直接上传完整候选对象。

写入 worker 对每个 item：

1. 从 `match_items` 读取候选 JSON。
2. 重新构造显式 `domain.TagPatch`，缺失字段保持 Keep。
3. 用客户端提交的 base revision 调用安全 Writer。
4. 单项冲突或写入失败写回 item `write_failed`，继续下一项。
5. 有成功项时重新扫描并为每项生成来源、字段 diff、前后 raw tags 和 revision 历史。

任务状态为 `succeeded`、`partial` 或 `failed`；文件原子替换和 SQLite 历史仍保持原有边界。

## 真实验证

使用 TestMusic 中 `心安之地` 的临时 MP3 副本：Apple 候选任务进入 review，确认一组字段后创建 write job；任务完成 `1/1 succeeded`，曲目 revision 推进，年份/音轨/流派等标签更新，历史来源为 `Apple / iTunes`，字段 diff 正确记录。原始 TestMusic 文件未被修改。

## 当前边界

- 当前审核字段按整组标准标签提交，ReviewDiff 的逐字段 checkbox 仍需提升为页面级状态后再精确传递。
- 批量写入目前先处理音频标签；候选封面仍使用单独的安全封面接口，后续可在 write item 中加入显式 artwork 选项。
- 取消、失败项重试和 SSE 事件将在任务队列完善阶段补齐。
