# 批量安全写入任务

验证日期：2026-08-20

## 流程

审核完成后，前端提交候选 ID、页面上仍选中的字段集合和每首曲目的基准 revision 到 `POST /api/v1/matches/jobs/:id/write`。后端只接受已持久化 match job 中的候选，不信任客户端直接上传完整候选对象。

写入 worker 对每个 item：

1. 从 `match_items` 读取候选 JSON。
2. 重新构造显式 `domain.TagPatch`，缺失字段保持 Keep；字段数组为 `[]` 时保持 no-op，只有省略字段数组（`nil`）才启用兼容性的全字段默认。
3. 用客户端提交的 base revision 调用安全 Writer。
4. 单项冲突或写入失败写回 item `write_failed`，继续下一项。
5. 有成功项时重新扫描并为每项生成来源、字段 diff、前后 raw tags 和 revision 历史。

任务状态为 `succeeded`、`partial` 或 `failed`；文件原子替换和 SQLite 历史仍保持原有边界。

## 真实验证

使用 TestMusic 中 `心安之地` 的临时 MP3 副本：Apple 候选任务进入 review，确认一组字段后创建 write job；任务完成 `1/1 succeeded`，曲目 revision 推进，年份/音轨/流派等标签更新，历史来源为 `Apple / iTunes`，字段 diff 正确记录。原始 TestMusic 文件未被修改。

## 当前边界

- 当前审核字段已支持标题、艺术家、专辑、专辑艺术家、音轨/光盘、年份、风格、歌词和候选封面的页面级逐项选择。
- 批量审核现在支持显式勾选候选封面；worker 先下载并校验来源图片，再以新的 revision guard 安全嵌入。若标签已成功但封面写入失败，会记录 `artwork_failed`，重试时只补封面并使用当前 revision。
- 任务中心支持运行中任务协作取消、失败/部分完成任务按失败 item 重试；单任务 SSE 推送进度，断线后以 GET 快照恢复。全局事件表、取消原因和更细粒度 item 事件仍是后续增强项。
