# 历史保留策略与批量刷新

## 本次实现

- 新增 `system_settings` SQLite 表和 `history_retention` 设置，默认每首曲目保留最近 20 条修订。
- 设置页选项为最近 3/5/10/20 次；`PATCH /api/v1/system/settings` 持久化并立即剪枝已有旧修订，后续每次写入也在同一事务中按曲目剪枝。
- `GET /api/v1/system` 返回实际监听地址和当前历史保留值；监听地址仍然只读，不能通过设置 API 修改。
- 历史列表查询继续带 `limit`，因此设置变更后前端显示窗口和数据库实际保留策略一致。
- 真实批量编辑任务完成后，曲库页等待任务快照并重新读取曲目，批量封面写入的尺寸、大小和健康状态不会停留在旧索引；Mock API 同步模拟这些字段。

## 边界

历史修订删除不会立即删除内容寻址的封面 blob，避免恢复或并发读取时出现悬空引用；后续可增加基于引用计数/标记清扫的 blob GC。
