# 抓取器策略与第一轮验证

验证日期：2026-08-20

## 已接入策略

| Provider ID | 数据源 | 使用的接口/实现 | 当前能力 |
|---|---|---|---|
| `musicbrainz` | MusicBrainz | `/ws/2/recording` Search | 标题、艺术家、发行、年份、时长、标签、MBID、CAA 封面引用 |
| `lrclib` | LRCLIB | `/api/get` metadata lookup | 标题、艺术家、专辑、时长、纯文本/同步歌词 |
| `apple` | Apple / iTunes | iTunes Search API `entity=song` | 标题、艺术家、专辑、音轨/光盘、年份、风格、时长、封面 |
| `netease` | 网易云音乐 | 网页 `cloudsearch/pc` + `song/lyric` | 默认关闭；歌曲、别名、同步歌词、专辑封面 |
| `kugou` | 酷狗音乐 | 网页搜索 + `krcs`/`lyrics.kugou.com` + `play/getdata` | 默认关闭；歌曲、LRC 歌词、歌曲封面 |
| `kuwo` | 酷我音乐 | 尚未启用 | 已注册为实验性、禁用策略 |

## 公共实现

- 编译期策略注册，不使用 Go plugin。
- 每个 provider 独立描述能力、健康、启用状态和配额说明。
- 公共 HTTP 层统一设置 context、超时、User-Agent、2 MiB 响应上限和结构化 HTTP 错误。
- MusicBrainz 默认 1 秒间隔；LRCLIB 默认 300 ms 间隔；Apple/iTunes 默认 3 秒间隔。
- 多个数据源并行查询；一个来源的 429/5xx/超时不会清空其他来源结果。
- 候选统一为字段级来源模型，并根据标题、艺术家、专辑和时长计算可解释分数。
- CJK 与拉丁文本在评分前统一小写并去除空格、标点；不会用逗号拆分艺术家。
- 网易云搜索会尝试完整元数据、标题+艺人和标题三种关键词，并对前一批候选补取歌词。
- 酷狗歌词通过候选 `id/accesskey` 下载 Base64 LRC，非 Base64 内容仍按纯文本兼容。
- 所有歌词统一去 BOM、零宽字符和 CRLF 差异；LRCLIB 精确查询 404 后会转入 `/api/search` 宽搜。
- 候选缺失的年份、音轨、风格等字段在前端不可选，不会清空本地已有值。
- LRCLIB 返回的同步歌词可由用户显式勾选后进入安全写入流程。

## 确定性测试

每个官方客户端使用自定义 `http.RoundTripper`，不依赖外网或监听端口，覆盖：

- URL 查询参数和 URL encoding。
- 官方要求的 User-Agent。
- JSON 字段映射和封面 URL 升级。
- LRCLIB 404 视为无候选。
- provider 503 标记为可重试且不影响其他结果。
- 中文标点归一化、候选排序、非空数组序列化。
- 前端真实搜索请求、provider 健康列表、缺失字段保护和歌词选择。

## 真实网络验证

使用 `TestMusic/再回首-姜育恒.flac` 发起多源搜索：

- LRCLIB 返回精确候选，综合分 `1.00`，包含同步歌词。
- Apple/iTunes 返回同名正式发行候选，综合分 `0.94`，包含音轨、年份、风格和封面。
- MusicBrainz 返回繁体艺人/发行候选，综合分约 `0.87`，字段来源正常。
- 候选抽屉共展示 8 个候选并按得分排序。
- 首次请求中 MusicBrainz 曾返回官方 503 busy；响应仍保留 LRCLIB 和 Apple 的 6 个候选，并把 MusicBrainz 标记为 `retryable`，验证失败隔离有效。
- 浏览器候选抽屉、字段 diff、来源、分数和歌词复选框正常，控制台无错误。
